# Purpose

> **Status:** Stable
>
> **Last Updated:** 2026-09-12

## The problem

Kizunia is a discovery platform. Competitions appear, open for registration, and close again
continuously. A student builder who only sees what they happen to browse will miss opportunities
that were a good fit — not because the platform did not have them, but because nobody told them
in time.

The naive fix makes things worse. A platform that notifies on every event trains users to ignore
it, and an ignored notification channel is worth less than no channel at all.

## What Notifications is for

Notifications exists to answer one question repeatedly and well:

> **Is there something happening on Kizunia that this specific user would want to know about
> right now?**

Everything in this subsystem — preference profiles, relevance scoring, thresholds, candidate
filtering, deduplication, history — exists to make the answer *no* most of the time, and
genuinely valuable when it is *yes*.

## Philosophy

**Relevance over volume.** A notification is sent because it is likely to be valuable to that
user, not because something happened. Quantity is never a goal; a day with no notification is a
correct outcome, not a failure of the system.

**Never trade relevance for quota.** If a notification policy asks for five candidates and only
three clear the relevance floor, three are sent. The floor is not lowered to fill the slot. See
[`relevance/threshold-and-selection.md`](../relevance/threshold-and-selection.md).

**Every notification has a reason.** Each notification is generated by exactly one *intent* — a
named business purpose with defined rules. A notification that cannot name its intent should not
exist. See [`intents/README.md`](../intents/README.md).

**The user is in control.** Users decide which intents they receive at all, and configure the
preference profile that determines what "relevant" means for them. Notification preferences never
silently alter the user's ordinary browsing, search or filter experience. See
[`preferences/filters-vs-preferences.md`](../preferences/filters-vs-preferences.md).

**Say nothing rather than guess.** Kizunia does not own external competition registration. It
knows only what it observed or what the user told it, and it never presents a self-declared fact
as verified. See [`scope.md`](scope.md).

**Built to be rebuilt.** The Phase 1 behavior is small and the subsystem it sits on is not.
Relevance algorithms, ranking, aggregation rules, channels and intents are all expected to change
repeatedly. The architecture is optimized for that change rather than for today's two
notification types — see
[`architecture/notifications/principles.md`](../../../../architecture/notifications/principles.md).

## What success looks like

A user should be able to say, of any notification Kizunia sent them: *I can see why I got this,
and I am glad I did.* If a notification cannot survive that sentence, the rule that produced it
is wrong and belongs back in [`decisions/`](../decisions/README.md) for revision.
